01 Executive summary

Creditcoin smart contracts cannot natively read Ethereum logs. When Circle marks an address Blacklisted on Ethereum mainnet USDC, CTC credit venues stay blind unless something bridges that fact. The naive bridge — a keeper calling setRestricted — makes a single key the compliance oracle.

FreezeWire inherits that Circle address-level flag into Creditcoin CC3 gated credit without a backend eligibility oracle. Path: real mainnet event → Attestcoin Merkle + continuity proof → BlockProver 0x0FD2 → FreezeWire consumer checks → EligibilityLedger → GatedCreditLine.

ETH Mainnet→ USDC Blacklisted→ Attestcoin proof→ 0x0FD2→ Consumer checks→ EligibilityLedger→ RESTRICTED→ draw reverts

Why Attestcoin

Only cryptographic inclusion + continuity lets CC3 accept an Ethereum fact without trusting a worker narrative. Removal test: without 0x0FD2, no path to RESTRICTED.

Why Creditcoin

The venue that must refuse the draw is where the proof verifies. Enforcement (GatedCreditLine) lives beside BlockProver on CC3.

02 The problem & the FreezeWire solution

The gap

External compliance facts (Circle’s address blacklist on Ethereum) and on-chain credit decisions on Creditcoin live on different machines of consensus. Bridging them with APIs, databases, admin setters, or manually maintained status lists creates a single point of failure: compromise, downtime, or censorship of that operator yields wrong freezes or continued lending to flagged addresses.

Desired property

An address becomes RESTRICTED only when the underlying Ethereum fact has been cryptographically proven and Creditcoin contracts independently verify that proof — not when a backend says so.

Oracle trap

setRestricted(addr, bool) onlyOwner
Key = compliance oracle. LP trusts server narrative.

FreezeWire

submitProof(calldata) permissionless
Invalid proofs revert on-chain. No setter exists.

Object of the gate

CEL freezes the instrument (e.g. issuer Paused → asset eligibility). FreezeWire freezes the counterparty after a proven Circle Blacklisted → address eligibility for new credit. Same Attestcoin spine class; different economic object. We do not claim overall superiority to CEL.

Attestcoin is not a label. It is the execution input.

03 Why Attestcoin is load-bearing

Ethereum event → source tx + receipt → Merkle inclusion + header continuity → BlockProver 0x0FD2 verifyAndEmit → FreezeWire consumer checks (status, emitter, topic, account, chainKey, window, txIndex) → EligibilityLedger state transition → GatedCreditLine enforcement

What 0x0FD2 proves: inclusion of the submitted encoded transaction under an attested header, plus continuity toward the attested tip.

What it does not prove: receipt success, Circle USDC emitter identity, event topic, or account. Those are FreezeWire consumer checks. Precompile success alone never writes Restricted.

Removal test: If Attestcoin / BlockProver 0x0FD2 is removed, FreezeWire cannot move an address to RESTRICTED — there is no owner setter, eligibility DB, or worker privilege that invents Circle’s blacklist.

09 Security model & consumer checks

After precompile success, FreezeWire still requires: receipt status, immutable emitter, event topic, account topic, expected chainKey, height window, Merkle-recovered txIndex, ordering, and replay. Failed verify / decode / status≠1 does not create Restricted.

BlockProver proves inclusion/continuity. Consumer validates receipt success and application semantics. This distinction is load-bearing for Attestcoin-depth scoring.

10 Replay protection · ADR-0017 Model A

key = keccak256(abi.encodePacked(chainKey, height, recoveredTxIndex))
  • Caller-supplied txIndex is informational only; on-chain index is recovered from Merkle path bits (TxIndex.sol).
  • Model A: after successful native verify and successful receipt scan (status==1), mark processed[key]=true. If no canonical USDC Blacklisted/UnBlacklisted log → emit ProcessedWithoutFact and return (do not revert). Eligibility unchanged. Retry → QueryAlreadyProcessed.
  • Do not mark replay if verify failed, window/chainKey failed, decode failed, or receiptStatus != 1.
  • Stale observations (older than account lastPos) are skipped, not whole-tx reverts.

Rationale: EVM reverts undo storage; processed=true; revert NoMatchingEvent cannot burn the key. Emitter is constructor-immutable, so Model B retries are useless gas.

11 Decoder, backend, frontend

Attestcoin decoder

FreezeWire vendors Gluwa EvmV1Decoder in-process. It walks the original log order (preserving logIndex for monotonic ordering), keeps only immutable-USDC logs with Blacklisted/UnBlacklisted topic0, and binds the indexed account from topics[1]. Decoy Transfer/Pause logs in the same receipt are ignored without failing the tx when a later match exists.

Backend (Render)

Node.js ≥20 · TypeScript · viem · zod · @gluwa/usc-sdk. Scripts: npm ci · npm run build · npm start · npm test. Stateless discovery + proof fetch + optional relay. Error sanitization, CORS, body-size limits, in-memory rate-limit pruning, bounded retries. Not the compliance authority.

Frontend (Vercel)

React 19 · Vite · TypeScript · Tailwind CSS 4 · viem · Three.js / React Three Fiber. Story spine: HOOK → EVENT → PROOF → CREDITCOIN → ACCESS. Commit state machine: PREPARED → WALLET SIGNATURE → BROADCAST → RECEIPT CONFIRMED → COMMITTED. UI does not claim success before chain confirmation; RELAY_DISABLED surfaces as NOT BROADCAST with calldata. Explicit LIVE / NOT_DEPLOYED / UNAVAILABLE / SIMULATION modes — production deploy does not enable simulation as the default path.

21 Known limitations

  • CC3 testnet only — not Creditcoin mainnet production; no audit claim.
  • Proof window (0,0) unbounded on live deploy — disclosed residual; production should bound freshness.
  • Owner can still retune setExpectedChainKey / setWindow (ops residual; not emitter swap; not Attestcoin bypass).
  • MockUSD is demo collateral — not Circle reserves on CTC.
  • Wallet path when relay disabled; in-memory rate limits; Render cold starts; limited FE E2E vs Foundry depth.
  • Demo account already RESTRICTED — two-account honesty (documented).
